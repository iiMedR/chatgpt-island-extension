# Architecture

## Technology and build

Manifest V3, React 19, strict TypeScript 6.0, Vite 7, Tailwind 4, Vitest, ESLint 10, and Prettier. Node 24 LTS is the pinned runtime. TypeScript stays on 6.0 because the installed typescript-eslint supports versions below 6.1; TypeScript 7 is incompatible. Vite's official React and Tailwind plugins serve the popup. Vite's build API emits a module worker and a standalone IIFE content script; no third-party extension integration or compatibility layer is needed. The TypeScript manifest is the single configuration source, emitted with each popup build. The lockfile pins the resolved dependency graph.

Compatibility references: [Vite requirements](https://vite.dev/guide/), [Tailwind Vite installation](https://tailwindcss.com/docs/installation/using-vite), [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), and [Chrome tabs permissions](https://developer.chrome.com/docs/extensions/reference/api/tabs). Automated checks validate the installed combination; they do not substitute for Chrome installation tests.

## Execution contexts

- Background: registers installation and Commands API listeners synchronously at module evaluation; development-only diagnostics. No polling, persistent selection state, or attempts to keep the worker alive. Each message has one bounded response-timeout timer, cleared on completion.
- Content: declaratively injected at document idle on the exact HTTPS ChatGPT origin, in Chrome's default isolated world. Owns the selection manager, message listener, and island controller. Reads only explicitly selected assistant text. Adds/removes its own overlay host without editing existing page messages or reading input values.
- Popup: short-lived React document. Queries the active tab on mount, checks exact URL origin, handles missing tabs/URLs and rejected API calls. Async updates are cancelled on unmount. Ready means supported origin only.
- Island: React UI in the content context's Shadow DOM; temporary messages, draft, context, and window geometry never enter the worker or persistent storage. Responses are deterministic local placeholders, not AI output.

Only directories with current responsibilities exist. Shared components, hooks, services, and types should be introduced when real consumers justify them.

## Permissions and communication

Only `activeTab` is requested. Opening the action or invoking a Commands API shortcut gives temporary access to the active tab's URL, per [Chrome's activeTab documentation](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab). No `tabs`, storage, scripting, broad host, AI host, or incognito permission. Static content injection is restricted to `https://chatgpt.com/*`.

`shared/messages.ts` defines a discriminated protocol with runtime guards: `FOUNDATION_PING` returns `{running:true}`, and `ISLAND_OPEN_REQUEST` returns a fixed trigger status. Requests contain no selected text. Content accepts recognized, exact message shapes from the same extension ID. Responses are validated in the background. Future close/toggle variants can extend this union; add request identifiers when asynchronous conversations require correlation. Worker restarts must not destroy authoritative selection/conversation state; keep temporary island state in the content context. Do not create a long-lived port just to defeat worker suspension.

## Styling isolation

Popup styles are isolated in their own extension document. CSS variables define light/dark background, foreground, muted, border, secondary surface, input surface, and radius tokens. Tailwind maps utilities to tokens, with system typography and system theme detection.

The island mounts into an extension-owned Shadow DOM and injects compiled `island.css?inline` there. Shared `styles/tokens.css` defines tokens on both `:root` (popup) and `:host` (island). Popup utilities remain Tailwind; island CSS is explicitly scoped, with its own box-sizing/typography reset and no global preflight or stylesheet insertion into ChatGPT. The host resets inherited layout and uses a viewport-fixed, pointer-transparent container; only the island receives pointer input. Shadow DOM isolates CSS, not secrets or trust.

## Security and future provider boundary

Only explicitly selected assistant text is read. No full-conversation collection, network requests, credential collection, HTML injection, remote scripts, or persisted data exist. Production uses MV3's default extension CSP. React renders plain text; future markdown must sanitize untrusted output and restrict links. Never use eval or remotely hosted executable code.

## Selection module (Milestone 02)

`selection-dom.ts` owns native Selection/Range access and ancestry validation. `selection-validator.ts` is pure text validation: trim boundaries, reject empty text and text beyond 10,000 UTF-16 code units. Internal spacing is unchanged. `selection-types.ts` defines the immutable text/source URL/timestamp/source type record. `selection-manager.ts` owns event scheduling, state, and lifecycle. `getSelection()` is the synchronous integration boundary used by the trigger controller, not a runtime message exposing selected text. The worker and popup receive no selected text.

## Commands and island trigger (Milestone 03)

The manifest declares the browser-scoped `open-island` command with suggested `Alt+Shift+E`, a valid Alt + optional Shift + letter combination under [Chrome's Commands API](https://developer.chrome.com/docs/extensions/reference/api/commands). No global command or DOM keyboard interception is added. Shortcut conflicts/OS bindings can prevent assignment or delivery. Installation/update checks use `commands.getAll()` and fixed development diagnostics; users customize their assignment at `chrome://extensions/shortcuts`. No preferences are changed automatically.

`background/commands.ts` registers one listener per service-worker evaluation, with an idempotent registration guard. It prefers the optional `onCommand` tab and only queries `{active:true,currentWindow:true}` when no tab is provided. Unsupported/inactive tabs, unsupported pending navigations, missing IDs, and failed tab queries are rejected. A single typed request is sent with `{frameId:0}`. Missing receiver/API rejection, invalid responses, and a two-second unresponsive-channel timeout produce distinct safe statuses. The timeout exists only during that request and is cleared in `finally`; no polling/retry queue or background text cache exists. A timeout is an acknowledgement failure, not cancellation of an already delivered request; no retry avoids duplicate emission.

`content/initialize.ts` owns the manager, message listener, and trigger callback. An extension-isolated-window disposal slot replaces a previous initialization, cleaning listeners, timers, and state. Non-cached pagehide disposes everything; BFCache pagehide uses the manager's existing clear/suspend rule. Invalidated runtime contexts return a fixed failure and dispose the manager when encountered. Reloading an extension can make its old receiver unreachable; the background handles this as a messaging failure and users refresh the ChatGPT tab. No code is dynamically injected to repair a missing content script.

`content/island-trigger.ts` retrieves the existing capture locally. It never reselects current DOM text or flushes pending selection processing: an immediate shortcut within the existing 80 ms debounce may have no capture yet. It reuses pure text validation and validates source type, supported origin, current conversation path, and a finite nonfuture capture timestamp. Expiration remains lifecycle-based (navigation, explicit clear, pagehide/reload/disposal), with no conflicting age-based TTL. Missing/invalid state emits no callback and returns a typed status. A newly invalid page selection still preserves an earlier valid record according to Milestone 02.

One successful request calls one typed `onOpen(IslandOpenPayload)` callback with immutable `{selectedText,sourceUrl,triggeredAt}` inside the content context. Repeated invocations may each call it once; no listeners are added per invocation. Callback exceptions become `handler-failed`, with no raw error/payload logging. Milestone 04 connects this callback to the real island controller in production and development; the fixed development receipt diagnostic remains optional. No DOM custom events, text-bearing runtime messages, external transmission, persistent storage, or prompt submission are introduced.

## Selection lifecycle and DOM assumptions

The manager debounces `selectionchange`, passive `mouseup`, and passive `keyup` for 80 ms, reads the live selection at processing time, and deduplicates unchanged captures. It never prevents default events. No MutationObserver or continuous document scan exists: dynamic responses are validated when selected. Only range-local elements and their ancestors are checked.

Assistant ownership requires both range endpoints to resolve to the same nearest semantic message: `[data-message-author-role="assistant"]` or `article[data-turn="assistant"]`. Role attributes take precedence. User messages, missing/unknown roles, shadow-root selections, disconnected nodes, multiple ranges, editable ancestors/focused controls, forms, buttons, sidebar/search/navigation regions, and `[data-chatgpt-island-root]` are excluded. Intersecting excluded elements or another message inside the range also cause rejection, even with valid endpoints. Markdown descendants need no class-specific logic. This deliberately conservative policy may reject selections near response controls or alternate markup.

These semantic attributes are DOM assumptions, not an official ChatGPT contract. Both forms have fixture coverage, but no claim is made that either matches every current ChatGPT rollout. Unknown layouts fail closed. No generated class names, full message text, message IDs, account data, or other tabs are collected.

The most recent valid capture is held only in the content context; invalid/collapsed/outside selections preserve it. Origin/path changes invalidate it, including conversation/project routes; query/hash-only changes do not. `currententrychange` (when available) and `popstate` handle committed SPA navigation without patching History APIs. A one-second URL-only check covers missing/isolated-world events; every capture and getter also checks the URL. See [Chrome Navigation API documentation](https://developer.chrome.com/docs/web-platform/navigation-api). URL checks do not inspect page content. Same-path conversation switches, if introduced by ChatGPT, would require a revised lifecycle signal.

Navigation cancels pending processing and remembers only weak endpoint references/offsets to reject an unchanged stale DOM selection without retaining old DOM trees. Pagehide clears and suspends capture; pageshow resumes after BFCache restoration. Non-BFCache pagehide disposes the manager. Disposal removes listeners, cancels timers, and clears the record; full reload/context destruction naturally drops memory. An explicit internal `clear()` follows the same invalidation rule. No text is stored in browser storage, sent through messaging, or transmitted externally. Development diagnostics contain only fixed lifecycle labels and rejection reasons; production removes the debug callback.

## Future provider integration

Future provider calls belong behind an explicit service boundary, with user consent for the selected context, minimal provider host access, bounded requests, abort handling, and safe errors. Never bundle API secrets or scrape ChatGPT session tokens/private endpoints. Credentials and provider choice need a separate design before implementation. This extension must not send into ChatGPT's composer or create history conversations.

## Floating React island (Milestone 04)

`content/island/island-controller.tsx` owns at most one host, shadow root, and live React root. A valid trigger mounts one `<Island>` into a child of an open shadow root on an extension-owned `[data-chatgpt-island-root]` element attached to `documentElement`. Root creation is lazy: no overlay DOM or theme/window listeners exist before opening. A stylesheet and mount element are the only shadow children. Repeated identical context renders the same root/session and increments a focus request; changed text/conversation starts a new keyed `IslandChat`, preserving the outer window's geometry. Close unmounts React, disconnects theme observers/listeners, removes the host, and releases context references. Reopening creates a fresh temporary session. The selection manager's existing capture remains independently available until its lifecycle invalidates it.

`Island.tsx` keeps temporary messages and input in React state, with typed `IslandMessage` records and a separate context payload. The UI is a non-modal accessible dialog: focus starts in the textarea, Enter submits nonblank input, Shift+Enter remains native multiline editing, and IME composition is respected. Questions append a user message and a synchronous deterministic assistant placeholder, explicitly labeled **Development placeholder**. No artificial waiting or network service exists. React renders all content as text; no HTML injection or markdown execution occurs. The conversation and context can scroll while header/composer remain visible. Escape/keyboard propagation handling is local to the island, with no document-level keyboard interception or permanent focus trap. Closing restores a still-connected prior focus target when focus was in the island.

`useIslandWindow.ts` owns typed rectangle/expanded/restore state. Pure helpers in `window-geometry.ts` enforce 460 × 520 defaults, 340 × 300 preferred minimums, and visible-viewport bounds, relaxing minimums when the viewport is smaller. Header/resize-handle pointer capture supplies movement events only during a gesture; there are no document pointer listeners. Header controls are excluded. Pointer-up/cancel/lost capture and unmount release gesture state. Header/handle arrow-key controls offer keyboard movement/resizing. Expansion uses a centered maximum 840 × 800 viewport-contained rectangle rather than fullscreen; restore clamps the saved geometry to the current viewport. Window and visualViewport resize/scroll listeners are mounted only while open, to handle viewport shrink/zoom/keyboard offsets. Extremely small viewports can inherently constrain readable content.

`theme.ts` prefers explicit HTML/body `data-theme` or `data-color-scheme` values, then `dark`/`light` classes, then an unambiguous computed `color-scheme`, with `prefers-color-scheme` as fallback. Only the root/body's relevant attributes are observed while open; there is no subtree conversation scan. System preference changes are observed too. The host theme overrides shared CSS variables, including color-scheme, without changing ChatGPT's theme or styles. The island uses restrained neutral surfaces, system fonts, monochrome controls, a soft shadow, rounded bubbles, and visible keyboard focus.

The selection manager gained an optional `onClear` lifecycle callback, connected to `island.close(false)`. Conversation navigation, pagehide/BFCache, explicit manager invalidation, and content disposal therefore close the UI and clear its chat without duplicating route detection. The existing idempotent content bootstrap disposes both manager and controller.

The content IIFE embeds React/React DOM and Vite-processed `island.css?inline`; no separately fetched CSS or web-accessible resources are needed. `styles/tokens.css` is shared by popup and shadow styles. Vite library builds now explicitly replace `process.env.NODE_ENV`, as recommended by [Vite's library-mode documentation](https://vite.dev/guide/build), so the production content bundle includes production React without a Node global dependency. No manifest permissions changed. Playwright is a development-only dependency; its browser fixtures use an isolated temporary profile and locally intercepted synthetic ChatGPT pages. Vitest excludes browser specs so each runner keeps its own lifecycle.

## Verification boundaries

Unit/DOM-fixture tests cover controller lifecycle, text safety, focus/submission, context replacement, themes, geometry and pointer-capture handlers. Build assertions check embedded React UI/CSS markers, absent development diagnostics, and absent unresolved `process.env.NODE_ENV`. The Playwright suite additionally targets the built unpacked extension at desktop/narrow sizes, but it could not launch Chromium in this environment (`spawn UNKNOWN`). A separate Opera preview rendered a synthetic fixture using a temporary copy of the built content bundle with only the ChatGPT origin string mapped to localhost and a mock Chrome runtime. That is rendered component evidence, not real extension installation, native OS shortcut delivery, or live ChatGPT compatibility. Native pointer interactions and full Chrome integration remain pending; see PROGRESS.md.
