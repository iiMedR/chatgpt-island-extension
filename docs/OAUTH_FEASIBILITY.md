## Authentication and inference are different contracts

Identity identifies an account; an ID token is not a bearer credential for plan inference. A future local flow must validate the signed identity and the grant independently. Its published authorize/token endpoints are https://auth.openai.com/api/accounts/authorize and https://auth.openai.com/api/accounts/oauth/token; callback examples use http://127.0.0.1:<port>/auth/callback, with identical URI in exchange. These URLs are documentation, not new network targets in the implementation. See the registration guide for full parameters and validation rules.

An authorized access token would target https://api.openai.com/v1/responses; model choices must come from the account-specific /v1/models catalog, not assumptions about the existing gpt-4.1-mini API-key configuration. Plan streaming must reach response.completed to count as success. Late failed/incomplete events and interrupted connections require separate handling. [Models](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

Current backend requests stream:false and max_output_tokens:2048. The plan preview requires streaming and rejects max_output_tokens plus other listed fields. Existing store:false, separate instructions, bounded selected context/history are reusable, but the provider serializer and end-to-end transport/UI are not a drop-in token substitution. No changes to the current model, output budget or SDK were made. [Preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## Conditional migration plan — not implemented

1. Resolve the product's open-source licensing/distribution eligibility or obtain the appropriate official private/commercial approval. Confirm the extension-plus-local-runtime use case with OpenAI if its scope remains unclear. Do not treat Git availability or npm private:true as an eligibility decision.
2. Verify the supported local registration/callback in an isolated test client before altering the extension. Keep OAuth credentials wholly in a protected local runtime; decide and test Windows ACL/OS credential protection, atomic replacement and process-level refresh serialization. Existing Origin/CORS controls do not authenticate local callers: add a separately reviewed extension/helper authorization/provisioning boundary before expanding local credential access.
3. Design narrow start/status/disconnect operations that return only non-sensitive state to the popup. Open a normal system-browser authorization flow from an intentional action; use the loopback listener, not an undocumented chromiumapp callback relay. No identity permission is needed merely to start a normal browser tab; reassess exact Chrome permissions after a verified design.
4. Keep reusable identity/client/host registrations independent from island state. A complete future callback must reject state/code/client/nonce/signature/audience/expiry mismatches and denial without overwriting active credentials. Add true expiry, refresh rotation and remote revocation handling; never label Chrome storage encrypted or keep tokens in the page/content script. Omit optional token-bearing URL hints to meet this project's stricter no-token-in-URL requirement.
5. Implement a separate ChatGPT-plan provider behind the existing AIAdapter boundary. Extend the Promise-only interface only as needed for typed deltas/terminal events, retain bounded input/retries/AbortSignal/ticket ownership, and route streaming through a cancellable local transport. Never silently use the paid API-key path when a plan request fails.
6. Close/dispose must still clear context/messages/draft/retry/partial output and abort work, while a future authenticated session remains independent. Explicit Disconnect stops inference, attempts documented renewable-session revocation, clears tokens and reports if remote revocation cannot be confirmed. [Sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)
7. Add mocked OAuth/PKCE/state/JWKS/scope/rotation/disconnect and SSE split-frame/terminal/error/cancel/stale tests, then run manual A–F from the supplied prompt on a working browser with an eligible consenting account. Verify successful inference separately from login and inspect real ChatGPT history. Only then consider a user-facing login and default-provider migration. Keep the API-key adapter until this succeeds, as an explicit developer fallback rather than automatic billing failover.

## Reuse and present limitations

Preserve the selection manager, command routing, one-root Shadow DOM controller, React layout, consent gate, immutable conversation manager, pure history pruning and stale-response cancellation. Current tokens do not exist in this app; the server still loads its developer API key only from environment. No ChatGPT cookies, local storage credentials, session extraction, undocumented backend-api routes or website composer automation are used. No OAuth/streaming test is claimed to pass, and no no-visible-history guarantee is asserted for an unimplemented flow. Existing 0.9.0 packaging, permission scope and API-key behavior remain intact.
